# T080: Remove autoplay from Trace mode

## 2026-07-24

### Summary
Removed automatic audio playback from Trace mode. In the current implementation, audio was auto-playing in both Listen and Trace modes when a card with audio loaded. Per the spec, only Listen mode should auto-play (since the audio is the prompt); Trace mode should require explicit user action (tapping the replay button), and Translate mode correctly never auto-plays.

### Changes
1. **SessionViewModel.swift** (lines 327-336): Modified `autoplayOnCardEntry()` to remove `.trace` from the autoplay condition. Changed from `presentedMode == .listen || presentedMode == .trace` to only `presentedMode == .listen`. Updated the accompanying comment to clarify that only Listen auto-plays and that Trace requires explicit user action.

2. **SessionViewModelTests.swift** (lines 336-351): Inverted the test that was asserting Trace auto-plays. Renamed `testTraceModeAlsoAutoplaysAudio()` to `testTraceModeDoesNotAutoplayAudio()` and changed the assertion from `XCTAssertEqual(fake.calls.count, 1, ...)` to `XCTAssertTrue(fake.calls.isEmpty, ...)` to verify that constructing a Trace SessionViewModel with an audio-bearing note does NOT trigger audio playback.
