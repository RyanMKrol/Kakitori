# T083: Free Study session logic (SRS-decoupled, endless)

## Completed 2026-07-25

### Summary
Built the logic + session-driving plumbing for Free Study (idea #8 Part B): an endless practice
loop over previously-seen cards that never touches the SRS or daily stats. This unit is logic
only — the UI entry point (which button launches it) is a separate unit.

### Implementation

#### Sources/Scheduler/FreeStudySource.swift (new)
- Pure, Foundation-only `FreeStudySource` mirroring `SessionQueue`'s style: no SwiftData, no wall
  clock, injected `RandomNumberGenerator`.
- Filters the given entries down to previously-seen cards (`state != .new`), shuffles them, and
  reshuffles-and-continues once the shuffled pool is exhausted — `next(rng:)` never returns nil
  while the pool is non-empty.
- `isEmpty` lets the caller detect an empty seen-pool and show a caught-up/empty state.

#### Sources/Features/Session/SessionViewModel.swift
- Added a dedicated `init(freeStudyDeck:mode:modelContext:clock:seed:audio:)` that builds the
  current card from `FreeStudySource` instead of `SessionQueue`, never calls
  `StatsRecorder.ensureDailyStats`, and leaves `dayTarget`/`dayCompleted` at 0.
- Added `isFreeStudy` flag and `advanceFreeStudy()`: the Free Study advance path (per the owner's
  decision, a single "Next / Keep going" control, not the four grade buttons) — pulls the next
  card from the endless source and persists nothing (no `scheduler.apply`, no `CardSchedule`
  mutation, no `StatsRecorder` call). `cardsWritten` is tracked in-memory only for display.
- `grade(_:)` branches early on `isFreeStudy` and delegates to `advanceFreeStudy()` before
  touching the note/schedule or calling the scheduler/StatsRecorder — a structural guard rail so
  Free Study can't leak SRS side effects even if the grading UI later routes through `grade(_:)`.
- `close()` skips `recordStudySeconds` when `isFreeStudy` is set.
- The normal SRS `grade(_:)` path is otherwise unchanged.

#### Tests/UnitTests/FreeStudyTests.swift (new)
- `FreeStudySource` unit tests: excludes `.new`, includes `.learning`/`.review`/`.relearning`,
  produces an endless shuffled sequence (pulls more items than the pool size and asserts every
  drawn id is from the seen pool), and an empty seen-pool yields nothing.
- `SessionViewModel` Free Study tests: grading writes no `CardSchedule` change (state, ease,
  interval, dueAt, stepIndex, lapses captured before/after and asserted unchanged) and no
  `DailyStats` row is created; `sessionCardCount`/`completedCount` stay at 0; `close()` doesn't
  record study seconds; an empty seen-pool deck yields `.caughtUp` with no current card.
- A regression test confirms the normal SRS grade path still writes `CardSchedule` and
  `DailyStats`.
