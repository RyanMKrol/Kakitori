# T082: Distinguish caught-up sessions from finished sessions

## Completed 2026-07-25

### Summary
Fixed the bug where starting a session on a deck with nothing to study (empty queue or daily target met) would display a hollow "Session complete — 0 cards written in 0 min" summary. The fix distinguishes between "finished a real session" and "there was nothing to study" by introducing a new `.caughtUp` phase.

### Implementation

#### SessionViewModel.swift
- Added `.caughtUp` case to the `Phase` enum to distinguish caught-up state from `.finished`
- Modified init to set `phase = .caughtUp` instead of calling `finish(now:)` when the queue has no cards to serve
- Updated `close()` to not record study seconds for caught-up sessions
- Ensured sessions with real cards still reach `.finished` with a summary unchanged

#### HomeView.swift
- Updated `sessionCoverContent` to branch on `activeSession.phase == .caughtUp`
- Added `caughtUpView` property rendering "All caught up" + "Nothing due right now" message
- Included a "Back to home" button with proper accessibility identifiers:
  - `session-caught-up` for the view
  - `caught-up-back-home` for the button
- Used consistent styling with the rest of the app (KakitoriTheme colors, rounded buttons)

#### SessionViewModelTests.swift
- Added `testCaughtUpWhenNoQueueAndNoDailyTarget()` to verify empty session enters `.caughtUp` phase with no summary
- Added `testCaughtUpWhenDailyTargetMetBeforeSession()` to verify when daily target is met before starting a session, the new session is caught-up
- Updated existing empty-start tests to expect `.caughtUp` phase instead of `.finished`
- Verified that normal sessions with cards still end in `.finished` with summary (no regression)
