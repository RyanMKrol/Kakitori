# T081: Fire card autoplay on view appearance, not in view-model init/grade

## 2026-07-25

### What was done

Refactored SessionViewModel to move autoplay trigger from synchronous calls in init() and grade() to view-driven calls on card appearance:

1. **Removed autoplay calls from SessionViewModel**:
   - Removed `autoplayOnCardEntry()` call from init() (previously line 147)
   - Removed `autoplayOnCardEntry()` call from grade() (previously line 204)
   - Kept `hasAutoplayed = false` reset in grade() so each card is eligible to auto-play once

2. **Made autoplay callable from the view**:
   - Renamed `private func autoplayOnCardEntry()` to `func triggerAutoplayOnCardAppearance()`
   - Kept the internal logic intact: Listen-only gate, autoplayEnabled check, hasAutoplayed guard
   - Method is now internal (not private) so the view can call it

3. **Wired up view-driven trigger in CanvasPaneView**:
   - Added `.task(id: viewModel.currentNote?.id)` modifier that runs on initial card id and each time the card id changes
   - Calls `viewModel.triggerAutoplayOnCardAppearance()` when the card appears
   - This covers both the first card on session start and each subsequent card after advancing
   - Paired with existing `.onChange(of: viewModel.currentNote?.id)` that clears the canvas

4. **Updated SessionViewModelTests.swift**:
   - `testListenModeAutoplaysAudioOnEntryAndOnAdvance`: 
     - Now verifies that init() produces 0 audio calls
     - Explicitly calls the trigger and verifies first card plays audio
     - After advancing, verifies no audio on grade(), then calls trigger for second card
   - `testTraceModeDoesNotAutoplayAudio`:
     - Verifies init() produces 0 calls
     - Even when trigger is called, Trace mode still produces 0 calls
   - `testAutoplayDoesNotFireWhenDisabled`:
     - Verifies init() produces 0 calls
     - When trigger is called with autoplay off, still produces 0 calls
