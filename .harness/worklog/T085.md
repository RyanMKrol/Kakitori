### Summary
Fixed the label-vs-behaviour mismatch on the Summary screen. Changed 'Study another' to dismiss the session and return to Home (with the deck list visible) instead of reopening DeckSetupSheet for the same deck.

### Changes Made
1. **Removed obsolete state**: Deleted `@State private var deckPendingRestudy: Deck?` from HomeView (line 14)
2. **Removed same-deck re-open logic**: Deleted the `onDismiss` handler in the fullScreenCover that was re-opening DeckSetupSheet for the pending restudy deck (lines 83-88)
3. **Fixed onStudyAnother routing**: Changed the callback to simply dismiss the session (`self.activeSession = nil; activeSessionDeck = nil`) instead of setting deckPendingRestudy and then re-opening setupDeck
4. **Preserved accessibilityIdentifiers**: Both buttons retain their stable IDs ('back-to-decks', 'study-another')
5. **Verified wording consistency**: Labels already distinguish the two buttons clearly - 'Back home'/'Back to decks' vs 'Study another script'/'Study another deck' - both land on Home with deck list visible, but the labels make the intent clear

### Behavior
- **Before**: Tapping 'Study another' on Summary would close the fullScreenCover, then the onDismiss handler would reopen DeckSetupSheet for the same deck that was just completed
- **After**: Tapping 'Study another' now simply dismisses the session and lands the user back on the Home deck list, where they can choose any deck (including a different one)
- Both buttons now have identical behavior (dismiss and return to Home), but remain meaningfully distinct via their labels
