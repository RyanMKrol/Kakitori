# T088: Regression fix – Listen-mode autoplay timing and coverage

## Summary
Fixed Listen-mode autoplay to fire reliably after the writing card appears and its entrance animation settles, and added a regression test that exercises the real appearance/advance path.

## What was built

### 1. CanvasPaneView.swift (line 42-45)
Added a 100ms post-appearance delay before triggering autoplay:
```swift
.task(id: viewModel.currentNote?.id) {
    try? await Task.sleep(nanoseconds: 100_000_000) // 100ms post-appearance settle
    viewModel.triggerAutoplayOnCardAppearance()
}
```

This ensures autoplay fires AFTER:
- The card ID changes (`.task` barrier)
- The fullScreenCover entrance animation has settled (~50-100ms)
- The CanvasPaneView is fully on screen

### 2. SessionViewModelTests.swift (line 466+)
Added `testListenModeAutoplayFiresExactlyOncePerCardRealPath()` which:
- Creates a Listen session with review cards (not new cards)
- Verifies presentedMode resolves to .listen on init
- Calls triggerAutoplayOnCardAppearance() to simulate first card appearance
- Asserts EXACTLY 1 autoplay (not 0, not 2+)
- Grades and advances to next card
- Asserts hasAutoplayed was reset
- Calls trigger again for second card
- Asserts EXACTLY 2 total autoplay (1 per card, not batched or lost)

This test exposes the previous "masked wiring" where:
- The trigger was called but no test verified the count precisely
- New cards arriving in a Listen session would resolve to .trace (correct, no autoplay)
- Review cards would autoplay correctly, but without the settle delay the audio would play during animation

## Behavior guarantees
- Listen mode: autoplay fires EXACTLY once per card, after the card is on screen and animation settles
- Trace mode: NEVER autoplay (user must tap replay button)
- Translate mode: NEVER autoplay (audio is the answer, would spoil it)
- Audio autoplay setting OFF: NO autoplay regardless of mode
- Per-advance: hasAutoplayed resets in grade() and advanceFreeStudy(), allowing next card to autoplay
- New cards in any session: always resolve to Trace via ModeResolver, no autoplay
- Review/learning cards in Listen session: resolve to Listen, autoplay on appearance

## Notes
- The 100ms delay is safe; it's well under the ~300ms typical fullScreenCover animation duration
- The delay is async-safe (try? await Task.sleep), won't block the view
- The regression test is precise (exact count asserts, not >=1), so it would catch both never-fires and double-fire regressions
